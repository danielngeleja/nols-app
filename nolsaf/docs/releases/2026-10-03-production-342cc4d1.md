## Recorded exception: applied migration corrected in place

- Scope: `20261002090000_add_platform_expense_ledger`, one expression in the
  GRANT_BONUS backfill. `CAST(JSON_UNQUOTE(details) AS JSON)` became
  `JSON_UNQUOTE(details)`.
- Reason: production is MariaDB 11.8.6, staging is MySQL 8.0.45. MariaDB rejects
  `CAST(... AS JSON)` with `ER_PARSE_ERROR`, so `migrate deploy` would have failed
  on production. No forward migration could fix this, because production must
  execute this migration first.
- Equivalence evidence: on staging the original and corrected SELECT return
  identical results; the corrected SELECT parses on the production clone. Staging,
  local, and production all had 0 `GRANT_BONUS` audit rows, so the backfill
  inserts nothing in any environment.
- History handling: staging and local `_prisma_migrations` rows were not
  rewritten. Their git-proven previous checksum
  `276129064ce4e13074357b6cc59031bf3050caa6647894fbf48c5cd7c79ee4d4` is recorded
  as a historical alias in `scripts/check-physical-schema.mjs`. The exact
  previous-to-current revision (`... -> 39c49a47db3caf6ae5fb216ac248b0481eb0c9e4e687e1ec93832243214e4a7d`)
  is pinned in `correctedMigrationRevisions` in
  `scripts/check-migration-integrity.mjs`; any other change is still rejected.
